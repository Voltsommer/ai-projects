我关注的不只是模型调用，还包括数据接入、安全执行、错误处理、持久化、自动化测试、CI 和可演示的产品界面。

## 核心作品

### 03 · 企业数据问答助手

用户可以上传 CSV / Excel，或连接 SQLite 数据库，再用自然语言提出数据问题。模型负责生成 pandas 代码或只读 SQL，程序执行计算，最后输出业务回答、图表和可展开的分析过程。

[查看完整项目案例](03-数据问答助手/CASE_STUDY.md)｜[查看运行说明](03-数据问答助手/README.md)｜[查看主程序](03-数据问答助手/app.py)

| 可核验结果 | 当前实现 |
|---|---|
| 数据来源 | CSV、Excel、SQLite |
| 数据接入限制 | 最大 10 MB、10 万行、100 个字段 |
| SQL 执行边界 | 单条只读查询、当前表权限、3 秒超时、最多 200 行 |
| Python 执行边界 | AST 允许清单、资源限制、DataFrame 副本执行 |
| 可审计性 | 生成逻辑、执行结果、最终回答同时保留 |
| 工程质量 | 91 项离线测试、GitHub Actions、编译和无密钥启动检查 |
| 故障降级 | 无 API Key 时仍可浏览和管理本地演示数据 |

这个项目重点展示：如何把大模型放进一条可控制、可测试、可追溯的数据分析链路，而不是让模型直接对整份数据进行心算。

## 工程质量与安全边界

- API Key 通过环境变量提供，不写入代码或 Git。
- SQL 与 pandas 使用不同的校验和执行边界。
- 人工数据库写入使用参数化接口，与 AI 只读查询分离。
- 聊天历史采用原子写入，损坏文件会隔离备份。
- 运行日志不记录 API Key、问题正文、SQL 或数据内容。
- 自动化测试不调用 DeepSeek，避免测试依赖外部服务。

受限 `exec` 和 SQL 授权属于作品集中的分层防护，不等同于容器或操作系统级沙箱。项目适合教学、作品展示和受控内部原型，不应直接开放给不受信任的公网用户执行任意输入。

## 快速体验核心项目

```powershell
cd "03-数据问答助手"
python -m pip install -r requirements.txt

$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
python -m streamlit run app.py
```

Windows 完成首次依赖安装后，也可以直接双击 `03-数据问答助手/启动项目.bat`。

未配置 API Key 时应用仍可启动。可以浏览示例数据库、查看表结构、人工新增或删除演示记录，但自然语言提问会被禁用。

运行离线质量检查：

```powershell
cd "03-数据问答助手"
python -m unittest discover -s tests -v
python -m compileall -q .
```
